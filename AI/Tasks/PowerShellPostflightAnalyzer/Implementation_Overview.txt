# PowerShell Parser Postflight Analyzer - Implementation Pipeline

This folder contains execution prompts for implementing POWERSHELL-PARSER safely in phased steps.

## Shared Contract
- Phase order is mandatory: Phase 02 -> Phase 03 -> Phase 04 -> Phase 05 -> Phase 06.
- Preserve these stable contracts across phases:
  - request validation model
  - response envelope schemaVersion 1.0
  - safety metadata and no-execution guarantees
  - deterministic ordering and bounded outputs
  - fail-closed behavior for invalid requests
- The tool must never execute PowerShell code.
- The tool must never create runspaces.
- The tool must never invoke pwsh, powershell.exe, Process.Start, or shell wrappers.
- The tool must never modify files.
- The tool must never perform remote operations.
- All findings are static-analysis findings only.

## Phase Goals
- Phase 02: Manifest, registry, security metadata, strict validation envelope.
- Phase 03: Parser SDK adapter and diagnostics normalization.
- Phase 04: AST projection and command discovery.
- Phase 05: Policy engine with versioned profiles.
- Phase 06: Optional routing and postflight integration.

## Cross-Phase Test Expectations
- Add deterministic tests as each phase lands.
- Keep snapshot shapes stable and versioned.
- Add negative tests for invalid inputs and safety boundary violations.
- Add at least one end-to-end postflight flow test by Phase 06.

## Output Format Required From Each Prompt
1) Summary
2) Files changed
3) Phase model and contracts
4) Tests added or updated
5) Validation results
6) Step-budget report (planned vs actual)
