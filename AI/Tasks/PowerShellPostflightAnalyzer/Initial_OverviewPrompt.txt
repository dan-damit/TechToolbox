I want to add a new governed external tool to TechAgent called POWERSHELL-PARSER.

Your task in this phase is to perform a full analysis and then produce a complete initial design for this tool. Follow the same workflow you used for the ripgrep tool evolution: analysis → phased plan → implementation prompts.

## OBJECTIVE
Design an optional, non-destructive external tool that wraps the PowerShell Parser SDK (`System.Management.Automation.Language.Parser`) and provides structured static analysis of PowerShell scripts.

This tool must NOT execute any PowerShell code. It must only parse, analyze, and return structured results.

## REQUIREMENTS

### 1. Tool Purpose
The tool should support:
- Syntax validation
- AST extraction
- Diagnostic collection
- Command discovery (Restart-Computer, Invoke-Command, etc.)
- Policy checks (disallowed commands, unbounded wildcards, Invoke-Expression, etc.)
- Normalized structured output

### 2. Tool Commands
Define a typed command set such as:
- PARSE
- GET-AST
- GET-DIAGNOSTICS
- FIND-COMMANDS
- CHECK-POLICY

Each command must have:
- Strict parameter schema
- Deterministic output shape
- No shell execution
- No side effects

### 3. Manifest Entry
Produce a manifest entry similar in style and structure to the ripgrep tool:
- Tool identity
- Executable or module resolver (if needed)
- Allowed commands
- Parameter definitions
- Output contract
- Safety constraints

### 4. Output Structure
Define the exact JSON structure returned by each command:
- SyntaxErrors[]
- Diagnostics[]
- AST[]
- CommandsFound[]
- PolicyViolations[]
- Metadata (line numbers, column numbers, severity, etc.)

### 5. Integration Guidance
Explain how TechAgent should:
- Route to this tool when generating PowerShell scripts
- Use parser results in postflight checks
- Keep parser analysis optional
- Avoid blocking runtime execution based solely on static analysis
- Enforce policy rules when required

### 6. Safety & Determinism
The tool must:
- Never execute PowerShell code
- Never modify files
- Never perform remote operations
- Never rely on shell invocation
- Always return structured, predictable results

3. Complete manifest draft for POWERSHELL-PARSER
4. Command definitions and parameter schemas
5. Structured output contract
6. Integration notes for routing and postflight
7. Next-phase implementation prompts
